# 趋势交易回测系统 · Trend Replay Backtest

纯本地的**双市场（期货 + A股）K线复盘与策略回测**学习工具。手动复盘与自动回测**共用同一套撮合、规则与成本逻辑** —— 一份成交逻辑，两种驱动（人工按键 vs 策略信号）。

不接任何实盘/券商接口，不做实时行情推送，不做 tick 级高频回测。

**在线试用**：https://puddingtower.github.io/trend-trading-backtest/ —— GitHub Pages 静态托管，打开就是真实行情，不用装任何东西。

在线版走浏览器直连东财（实测上游回显任意 `Origin`，含 `null`，所以静态托管也能取到数）；本地版 `python start.py` 额外提供 `/api/kline` 代理与 IndexedDB 缓存，上游不可用时可降级。

### 在线版 / 本地版功能对照

| 停牌缺口标注 / 复权连续性校验 / 当日无负债结算 | ✅ `src/markets/dataQuality.js` | ✅ |
| 高级报表与导出 | ✅ 月度热力图、水下曲线、交易分布、基准对比、HTML/CSV | ✅ |
| 盲复盘 / 交易日志与分组统计 | ✅ IndexedDB | ✅ 同一个 store |
| 自选池（分组、批量拉数据、持久化） | ✅ IndexedDB | ✅ 同一个 store |
| 代码-名称检索与交叉校验 | ✅ JSONP 直连代码表 | ✅ 同样 JSONP 直连（`/api/resolve` 留作备用） |
| 截图识别导入 | ✅ 浏览器 tesseract.js（WASM，模型首次现取） | ✅ 优先 rapidocr（中文最好，不下载模型），没装则同样降级到浏览器 |
| 文本粘贴 / CSV 导入（零 OCR 兜底） | ✅ | ✅ |
| 报告导出（HTML / CSV / Markdown 纪要） | ✅ 纯前端生成下载 | ✅ |
| `/api/kline` 代理降级 | ❌ 静态托管没有后端（前端会跳过这一通道，不再空打 404） | ✅ |
| 真实K线夹具 `fixtures/` | ❌ 不入库 | ✅ `start.py` 自动补抓 |

> 结论：**除了「本地代理降级」和「夹具」两条，在线版与本地版是同一套功能**。
> 截图 OCR 在线用浏览器 WASM（英文模型 10.9MB / 中文 20.2MB，只在第一次识图时现取一次），
> 本地优先用 rapidocr（中文更准且不下载模型）。图片在任何模式下都不会上传到第三方。

>
> 识图导入**刻意不赌 OCR 的裸准确率**：抠出的每个代码都要过 `symbolMeta` 解析 + 代码表名称交叉校验，
> 同码多义（`000001` 平安银行 / 上证指数）和解析失败的行进「需确认」列且**默认不勾选**，
> 错代码绝不静默入池。

## 启动（一条命令）

```bash
python start.py
```

它会：起本地服务器 → 夹具缺失时自动补抓 → 打开浏览器。
端口被占会自动往后找一个，并同步告诉抓取脚本用哪个端口
（之前必须手动开两个终端、还得保证顺序，那不算开箱即用）。

```bash
python start.py --port 9000        # 换端口
python start.py --no-fixtures      # 跳过抓夹具（纯手动复盘）
python start.py --no-browser       # 不开浏览器
python run_local_server.py         # 只想跑服务器时也可以单独用它
```

> **必须通过这个服务器访问，不能双击 HTML 打开。**
> 前端用 ES modules（`<script type="module">`），浏览器在 `file://` 下会以 CORS 为由拒绝加载模块；
> 而且 `/api/kline` 行情代理也依赖这个服务器。

换端口：`TREND_PORT=9000 python run_local_server.py`

### 行情夹具

真实K线夹具**不入版本库**（避免把上游抓取数据再分发）。`python start.py` 会自动抓；
想手动做也可以，注意抓取脚本走的是本地 `/api/kline` 代理，所以**服务器必须先起**：

```bash
python run_local_server.py &        # 服务器先跑着
python tools/fetch_fixtures.py      # 另开终端，或后台执行
```

生成 `fixtures/` 下约 17 份 JSON（2015→今，覆盖黑色/化工/农产品/金属/股指/A股/ETF/指数）。
没抓夹具时测试会**自动 skip** 相关用例而不是报错。

### 自选池与识图导入

底部 **「⭐ 自选池与识图导入」** tab：

- 手动加品种：输 `600519` / `sh000001` / `rb2610` / `螺纹钢主连` 都行，解析交给 `src/markets/symbolMeta.js`；
  重复判重按 `secid`，所以同一个主连的三种写法不会变成三条。
- **识图导入**：拖入截图、点上传，或直接 Ctrl+V（iPad 上长按粘贴）粘贴行情软件的自选列表截图。
- **文本粘贴导入**：从行情软件复制整列代码粘进来（TSV / 空格分隔），零 OCR 依赖，永远可用。
- 两种导入都会先出**预览确认表**：每行给 OCR 原文、抠出的代码、代码表回填的名称、状态。
  同码多义与未识别的行默认**不勾选**，改代码或取消勾选后自己决定；确认无误再点入池。
- 「🔽 批量拉本组日线」逐只取数写进 IndexedDB，不换图、不动当前复盘进度。
- 「🔁 月份合约换主连」把本组的 `rb2701` 这类具体月份一键换成同品种主连（顺序不动、已是主连的原样保留、
  换出来撞车的月份合约直接丢掉并说明）。**为什么值得一个按钮**：月份合约只有上市以来那几个月，
  日线撑不起一次回测；能改的不是市场，是让他别一个个重敲代码。

### 数据能有多长（以及为什么常常没那么长）

三种「短」是完全不同的病，混在一起就会一直找错方向：

| 现象 | 原因 | 解法 |
|---|---|---|
| 月份合约日线只有几个月 | 合约本身只活了这么久，市场事实 | 换主连（自选池那个按钮，或品种下拉选 `RB0` 这类） |
| 主连日线有几年 | 东财主连是上游拼好的连续序列 | 长期回测就用这个口径 |
| 60 分钟只给最近约一个月 | 上游分钟线本身就这么浅，不是前端截断 | 已做 `end` 游标往前翻页回填；翻不出新 bar 就停手并如实报 |

分钟线回填走的是 `end=<最早日>&lmt=500` 这条分支，最多 6 页。这条分支和 `beg+end` 那条
在上游是两套行为（`run_local_server.py` 里记着：带 `beg` 时 `lmt` 会被忽略），所以值得试一次。
**但它不保证挖到更多** —— 上游真没有更深的，这里就照实说"只到某天为止"，要长周期分钟回测请走 CSV 导入。

**4 小时线是本地合成的**：东财根本没有这个 klt，`src/data/periods.js` 从 60m 合成。
口径是**按交易日锚定、当日连续 4 根 60 分钟并 1 根**（文华 240 分钟），夜盘归下一交易日；
凑不满的尾巴照样出一根并用 `spanBars` 标真实根数，**绝不补造 bar**（补出来的假 bar 会把 ATR 和均线一起压低）。
时间戳保留到分钟（新浪 60m 原始形如 `2023-11-07 15:00:00`，只去秒）—— 截成纯日期会让同一天所有 bar 同键、
排序退化成保持倒序，合成出来的 open/close 整根反掉，而且肉眼很难发现。

## 服务器接口

| 路径 | 作用 |
|---|---|
| `GET /api/kline` | 行情代理。参数 `secid / provider(eastmoney,sina) / period(daily,weekly,monthly,60m,30m,15m,5m,1m) / adjust(none,qfq,hfq) / count / beg / end`。**`4h` 不是上游参数**：前端由 `src/data/periods.js` 拿 `60m` 合成；发 `period=4h` 到这里会被明确拒绝，不会兜成日线。`provider=sina` 的日线带 `settlement`（交易所结算价），东财 kline 不带 |
| `GET /api/resolve?q=` | 代码-名称检索。**现在只是备用通道** —— 前端改为 JSONP 直连代码表（searchapi 不回 CORS 头，但 `cb=` 的 JSONP 形态浏览器能直接用），所以线上也有这个能力 |
| `GET /api/health` | 服务与 OCR 引擎状态。前端用它判断这台主机上有没有本地后端（静态托管上不发这一发请求），以及识图该走 rapidocr 还是降级到浏览器 |
| `POST /api/ocr` | 截图识别（需 `pip install rapidocr_onnxruntime`；未装返回 501，前端自动改走浏览器 tesseract.js） |

`secid` 由前端 `src/markets/symbolMeta.js` 解析后传入，服务器不重复实现代码解析。
格式：`1.600519`(沪) / `0.000001`(深) / `113.rbm`(上期所主连) —— 交易所编号 113上期所 114大商所 115郑商所 142能源中心 220中金所 225广期所。

## 回测口径（重要，决定了结果可不可信）

这些不是文档里的提醒，而是 `tests/backtest.test.js` 里可断言的规则：

1. **信号在第 i 根产生，成交固定在第 i+1 根开盘**。不提供"当根成交"开关 —— 那个口径等于用未来信息。
2. **跳空穿透止损按开盘价成交**，不按止损价。按止损价记账会少记真实亏损。
3. **同一根内止损与止盈都可能触发时，先算止损**（悲观优先）。
4. **`priorExtreme` / Donchian 通道不含当前 bar**，否则等于用今天的最高价决定今天的突破。
5. **确定性**：同一输入两次运行，交易列表与权益曲线逐字节相等。
6. **复盘工具里所有叠加指标只喂已揭示的 bar**，杜绝未来函数。
7. **账必须闭合**：`期末权益 = 本金 + Σ各笔净盈亏`，且权益曲线每一点都等于 `现金 + 占用保证金 + 浮动`。
   两个引擎各有断言（`tests/boundary.test.js` 覆盖裸信号/止损止盈/分批止盈+移动止损/做空+金字塔/逐日盯市/名义仓位六种口径，
   `tests/portfolioEngine.test.js` 覆盖共享池与强平）。这条等式是组合引擎唯一的硬验收 ——
   收益率算错会难看，现金记漏只会**好看**，没有断言就永远发现不了。
8. **收尾平仓的费用属于最后一根**：末根收盘强平之后要回写曲线末点，否则末值偏高一个平仓费，
   而多品种组合按末值相加时误差会累加。
9. **保本/追保/强平都在下一根开盘成交**：判定用本根收盘或已走完的极值，成交在次根 —— 不给"当根假设能出掉"的口径。
10. **板锁对开仓与平仓一视同仁**。封死的跌停板上排的是卖队，你想卖就是卖不掉，这跟你在开空还是在平多没有
    关系。规则层以前给平仓开了"永远放行"的后门，而趋势策略的止损恰好大量打在跌停附近 —— 等于在最该痛的
    地方装作不痛。封没封死只看**与成交路径一致的锚定价**：开盘成交看开盘价，盘中触碰看那一侧极值；
    拿收盘价倒推"这根到底封没封死"又是一次前视。被拦下的委托不下岗，下一根继续判（真实账户就是被闷在板里）。
11. **Walk-Forward 默认留净化间隔**（宽度取样本内最长持仓身长，上限 `isLen/4`），缝宽进 `summary` 而不是当隐形设置。
    IS 与 OOS 贴着时，跨缝持仓会把"参数选择的结果"偷渡进考卷。要旧口径显式传 `embargoBars: 0`。
12. **因果性由探针断言，不靠人眼 review**。`src/validation/leakProbe.js` 两条判据：前缀一致性（把序列截到
    第 i 根重算，第 i 个信号必须与全序列下逐字段相等）与未来不变性（改写某天之后的行情，这天的权益与
    已了结成交不许有任何变化）。测试里每类泄漏都配了"必须报红"的自检 —— 这两条自检当场抓出过探针自己的
    两个盲区：整体放大未来对**比率型**依赖（波动率、收益）免疫，必须改写未来才测得出；成交是按平仓先后
    记录的，按开仓序号逐条比会串位误报。
13. **跑批与界面必须走同一条规则路径**。`tools/backtest.js` 一度不注入 `rules`、自己拼的 spec 连 `market`
    都没有，于是 A股 T+1 与涨跌停板锁在跑批里整段不存在，同一个策略在 CLI 和界面上给出两个答案。
    现在两边共用 `resolveTradeSpec`，汇总表多了「板锁拒开 / 板锁拒平」两列 —— 拦截次数不报出来，
    保真的成本就只藏在权益曲线里没人看得见。
14. **图上只许出现真实存在的K线**。取数失败时以前会静默换成 260 根随机游走（只弹一条 2.6 秒的 toast），
    现在 `MockDataGenerator` 连文件一起删了，`*9999` 仿真预置盘也从下拉里移除：拉不到真数据就留白 +
    持久横幅逐条报"哪条通道、什么错、下一步做什么"。合成数据画的权益曲线比空白危险得多。
    回归守卫在 `tests/realdata.test.js`（扫生产代码，注入一行 mock 就会报红）。
15. **Y 轴默认对数、复权默认后复权**。止损/止盈是按百分比定的，线性轴上"3000→3300"和"6000→6300"
    画出来一样高但一个是 +10% 一个是 +5%，在同一张图上量两根K线必然量错。对数轴下已断言
    等率涨跌映射成等距像素；价格含 ≤0 时（前复权会把早年扣成负数）自动退回线性并在轴上标「线性」。
16. **上游没有的周期只能从更细的真实周期现算，不许拿别的周期顶替**。东财 `klt` 表里没有 240，
    把 `period=4h` 直接发过去会被 `KLTL[period] || '101'` 静默兜成日线、画出来却标着 4 小时。
    所以 4 小时走 `aggregateIntraday`：按交易日锚定、连续 4 根 60 分钟并 1 根（文华"240分钟"口径），
    凑不满 4 根的尾巴照样出一根并用 `spanBars` 标出真实根数 —— 绝不补造 bar。
    底料序列没有钟点时（新浪 60m 实测只给日期）在同步提示里明说这不是真正的 4h 时段划分。

17. **周期口径只有一个入口，且拿回来的序列要验间隔**。所有"这个周期该向上游要什么、拿回来怎么合"
    收在 `src/data/periods.js` 的 `resolveBars`，主图与自选池批量拉取共用它 —— 两处各写一份已经出过两次事故：
    ① 批量拉取把 `periodSelect` 的值直接发给 `fetchBars`，4小时 被兜成日线并按 4h 键写进缓存；
    ② 新浪只有 daily/60m 两个服务，问它要周线会拿到**日线**还返回 `ok:true`，于是 1361 根日线
    被按 weekly 键存进 IndexedDB，之后每次开周线都"秒开"那份坏数据。
    现在：没有的服务明确拒绝（前端与 `run_local_server.py` 两侧同口径），并且 `periodSpacingOk`
    按相邻 bar 的中位间隔校验所标周期，上游给错、缓存已被污染都拦得住，拦不住就退回本地日线聚合。
18. **组合回测只吃日线及以上周期**。`PortfolioEngine` 的日历与"日期→下标"都按 `date` 前 10 位归并，
    分钟级序列会被静默压成一天一根（只剩最后一根参与撮合），权益曲线看着正常其实是日线。
    现在带钟点的序列直接拒跑并说明原因，而不是给一个安静的错数字。
19. **没有行情时读数必须一起清空**。取数失败把图擦成空之后，顶栏报价、买卖按钮上的 `@ 价格`
    曾继续显示上一个品种的数；`syncUI` 在没有 bar 时还拿硬编码的 `4200` 去算动态权益。
    现在报价显示 `--`/`无行情`，持仓存在时按成本价挂（浮动 0），不再凭空造一个价格。

成本口径：期货按品种乘数/tick/保证金/手续费（平今仓单独计费）；A股 1手=100股、佣金万2.5最低5元、卖出印花税、过户费。

## 叠加指标（关键位）口径

这一层的原则是：**一条线只在它还成立的区间里存在**。之前不是这样 —— 一期的日枢轴、
一条早被突破的摆动位、一个走完的形态，都会被拉成横贯全屏的线，看着全都还有效。

- **Pivot 关键位**：每组枢轴只画在自己的 `[fromIdx, toIdx]` 内，收盘即截止；
  同时显示最近 `visibleSets`（默认 3）期，历史期淡出且不叠标签。日级枢轴本来就是当日有效的报价。
- **HL 摆动位**：被收盘价穿越即记 `brokenAtIdx` 并标「破」，线截止在那一根；
  名额优先给还活着的线，否则「2010 年碰过 9 次」会永久霸占仅有的 6 个位置。
- **形态识别**：确认后逐根核对，给出 `在途中 / 已突破 / 已达标 / 已失效 / 已过期` 五态之一，
  走完就给出 `resolvedAtIdx` 并截止。判定顺序悲观优先（先看止损再看目标），与回测内核第 3 条同口径。
  迟迟不破颈线的形态会过期消失，而不是长期挂着当"机会"。
- **供需区**：色带截止在被收盘穿越的那一根并标「已失效」（旧的实现是直接丢弃，读者不知道它曾成立过）；
  脱离棒仍是最新一根时标「形成中」，右边界画虚线。名额按 `强度 × 新鲜度衰减` 排，失效区打三折 ——
  `freshness` 这个字段以前算了但没人用，所以全历史最强的老区永远占满名额。
  口径同时改成「1~3 根窄幅棒构成盆地 + 随后 ≤3 根内完成脱离」：原口径要求单根窄棒后**紧跟一根走完 1.8ATR**，
  实测螺纹钢 1900 根日线里够格的窄 base 有 233 个、单根最大脱离却只有 1.76ATR，
  门槛永远够不着，于是这个叠加层恒返回 0 个区 —— 开了开关看到的是空白。改后同一数据集出 38 个区。
- **周线/月线分桶**不解析 `new Date("YYYY-MM-DD HH:MM")`：iPad/Safari 对它返回 Invalid Date，
  60m 数据上切周线枢轴会全体归进同一个坏 key。**「回测起点」切片以前就栽在这里** ——
  同一形状的 date 让 `isNaN` 判真，起点选择在平板上等于没这个功能；现在只按字符串比 `YYYY-MM-DD`。
- **持仓止损/止盈胶囊读的是当前线价，不是建线那一刻的止损%**：拖动只改 `p1.price`，
  而 `tagPct` 是按下单时的止损% 烘进去的常数 —— 于是线拖到哪都写着 `-9.0%`，看着像线坏了、
  其实撮合用的是拖后的价。现在一律用 `levelPct(price, refPrice, dir)` 现算，空头自动翻号，
  拖离默认值时补一个「·已拖」，拖回原值标记消失。

**历史长度由三件事决定，缺一件就只剩一个月可看**：

- **写法**：`rb2701` 是具体月份合约，东财只有它上市以来那几十根 —— 这是市场事实不是数据缺失。
  要长历史必须用主连写法 `RB0` / `rbm` / `螺纹钢主连`（解析后都是 `113.rbm`）。载入具体合约且根数不够时，
  图上会挂横幅并给「改用主连 RB0」一键切换。
- **周期**：日线主连能回到 2015（东财 `rbm` 实测 2859 根，2015-01-05→2026-10-13）；
  60 分钟上游本来只保留几周至几个月。前端现在用 `end` 游标最多往前翻 6 页，翻不出新 bar 就停手；
  挖不到更深的数据会如实说明，长周期分钟回测仍建议走 CSV 导入。
- **通道**：新浪这条的主连历史比东财更深 —— `RB0` 回到 **2009-03-27**，`EG0` 从 2018-12-10 起。
  日线服务名已改为 `InnerFuturesNewService.getDailyKLine`，实测更新到当前交易日并带交易所结算价；
  旧 `IndexService` 名字失效被误写成"新浪数据冻结"。它此前一直坏还有第二个原因：接口发的是
  `var cb=([...])` 赋值而不是 `cb([...])` 调用，前端回调被赋值覆盖，固定 8 秒超时。
  主连代码新浪只认 `<品种>0`，所以 `symbolMeta` 额外给出并在自选池里持久化 `sinaCode`。

**仍然是边界 / 非目标（别当成已有能力）**：

- **没有 tick 级数据、不接实盘、不推实时行情**。项目定位是复盘/回测学习系统；数据 schema 预留了字段，
  但不实现高频撮合，也不碰券商接口。
- **跨品种对冲保证金优惠没有硬编码**。国内交易所的套利持仓减免按品种对/交易所规则变化，宁全额占用（偏保守）
  也不猜一个会改变爆仓时点的比例。组合支持多品种同时持仓，但没有内置跨品种价差/套利腿策略 —— 那是策略层的活，
  不是撮合层该偷偷替用户决定的事。
- **组合共享池只支持日线及以上周期**：它的日历与「日期→下标」按 date 前 10 位归并，分钟级会被静默压成一天一根，
  所以 `PortfolioEngine` 遇到带钟点的 bar 直接拒跑，而不是拿日线结果冒充分钟级结果。
- **交易日历有覆盖范围**：A股 1990-12-19 → 2026-10-19，期货 2009-03-27 → 2026-10-19。
  数据只比日历多一两天时（最常见：最后一根是今天）用覆盖段 + 实际存在的 bar 日期补齐并标 `calendarPartial`；
  完全超出才退回「只报自然日缺口」。延长日历要重跑 `python tools/fetch_trading_calendar.py`，
  不能凭周末规则硬猜未来的休市安排。
- **复权修复只修「看起来像除权」的跳空**：比率在 [1/4, 4] 之外不硬修（那更像代码错配或数据错位）。
  东财源如果新浪结算价也补不上，逐日盯市仍会回退收盘价，并在返回值里写明代理了多少根。
- **蒙特卡洛重放的是"已发生的交易"**。它回答"顺序换一下会怎样"，不回答"策略本身是不是真的有效" ——
  后者要靠样本外与真实成交，不靠重排。
- **策略对比比的是「默认参数」而不是「调优上限」**：每个策略各用策略库默认值，跑在同一品种、同一区间、
  同一资金/手数/滑点与市场规则上。它适合回答"这段行情里哪套逻辑更稳、彼此是否互补"，
  不能拿来给策略排名；参数稳不稳要看寻优的邻域稳健度与 Walk-Forward 效率比。
- **对比页的「等权组合」是研究口径**：各策略日收益等权平均（每日再平衡），不含撮合、保证金与交易约束，
  只用于观察互补性，不能照着下单。可交易的多品种组合走「组合回测」的分仓/共享池引擎。
- **相关性矩阵只衡量日收益的线性相关**：低相关不等于危机时还能分散（尾部相关性会上升），
  高相关则说明几个策略大概率在赌同一件事。样本里的相关性也不保证未来成立。
- **默认策略没有一个是"能赚钱的策略"**。真实数据跑批与寻优实测结论一致：没有一个策略稳定跑赢买入持有，
  螺纹钢上寻优得到的最优 Sharpe 也只有 0.143；参数一调成绩就翻脸（典型过拟合信号）。
  **引用这些数字前先看口径**：它们出自 `tools/backtest.js`，而 M9 之前那个跑批不注入 `rules`，
  等于在**绕过 A股 T+1 与涨跌停板锁**的路径上算出来的；补上规则后各策略成绩普遍变动且方向不可预测
  （有升有降，因为"拦住一次追涨"和"拦不住一次止损"是两件事）。同时 M9 起 Walk-Forward 默认带净化间隔，
  历史的 IS/OOS 效率比也一并作废。结论本身（没有稳定跑赢买入持有）在重跑后依旧成立，但**具体数字需要重跑才能引用**。
  Walk-Forward 的效率比、热图的孤峰判定、蒙特卡洛的 P95 回撤，都是用来把这件事量化出来的。
  **这个项目的价值在验证框架，不在这几个默认参数。**
- **叠加指标是启发式，不是信号**。形态识别与供需区都在注释里写明了口径和保守取向；
  图上标出一个不存在的头肩顶比不标更有害，所以宁可少报。

### 2026-10-20 这轮清掉的已知问题

- **交易日历**：内置 A股/期货真实开市日，`annotateGaps` 没有参照序列时也能区分长假与停牌；
  节后首日不再被误标 `stalePrevClose`，只有真的停牌若干交易日才跳过板锁。
- **复权断崖**：`repairAdjustmentGaps` 把超过板幅的隔夜跳空按复权因子接回；回测面板新增「修复杂复权断崖」勾选框，
  默认关闭，勾选后体检与回测都用修正后的序列。超出 [1/4, 4] 的比率不硬修。
- **结算价**：新浪日线的 `s` 字段是交易所结算价，逐日盯市优先用它；东财源缺失时回退收盘价，
  返回值里分别写 `realBars` / `proxyBars`，不再笼统写着"用收盘价代理"。旧缓存没有 `settlement`，
  重新点一次「在线同步」即可补上（只补结算价，不动 OHLC；补不上就继续用收盘价）。
- **组合层部分平仓/加仓**：`PortfolioEngine` 按条件单的 `qtyLots` 部分平仓、按 `ADD` 单金字塔加仓；
  保证金按比例释放、开仓费按比例摊、平仓费按本次手数算，账闭合断言覆盖这两种路径。
- **新浪通道**：日线服务名改为 `InnerFuturesNewService.getDailyKLine`。旧服务名失效被误写成"新浪数据冻结"，
  实际日线一直更新到当前交易日；日线现在带结算价，CSV 导入也认 `settlement` / `结算价` 列。
- **界面可用性**：策略参数改成中文名 + 单位 + 悬浮说明，`mode` 用 EMA/SMA 下拉，并加「恢复默认」；
  按仓位算法隐藏无关输入；数据体检逐条显示而不是挤成一行；0 笔成交或少于 10 笔时有专门提示；
  去掉重复的「4 小时」周期选项；负收益结果补一句"默认参数不是推荐参数"。
- **研究面板的品种规格错配**：它一直读 `chart.currentSymbol`，而图表模块只有 `backtestCode`，
  于是永远落回 `RB0` —— 在 EG/MA 这些乘数恰好也是 10 的品种上不容易发现，换黄金/铜/股指后保证金、tick、成本
  会全按螺纹钢算。现在研究面板读 `backtestCode`；该字段改为「数据真正进图时」才更新，取数失败不会把旧数据的规格换掉。
- **本地静态缓存**：`run_local_server.py` 的静态响应补 `Cache-Control: no-store`。此前只有 Last-Modified，
  改完 ES module 普通刷新仍可能执行旧逻辑（本轮开发当场复现：勾选交互改了、页面还在跑旧处理器）。
- **研究面板顶部资金/手数/滑点**：每次重绘都会弹回默认值。现在重绘前先保存，切 tab、勾选、跑完对比都不再丢用户填的数。
- **新增「策略对比」页**：同区间并排 2–6 个策略（各自默认参数），给指标表、归一化权益叠加、日收益相关性矩阵、
  等权合成曲线与同手数买入持有基准；勾选变化或切换品种后会明确标出"表里还是上一次的结果"。纯函数在
  `src/report/strategyCompare.js`，9 条单测覆盖对账、相关性性质、组合复算、CSV 转义与拒绝路径。
