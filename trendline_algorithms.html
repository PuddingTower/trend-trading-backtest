划线不是玄学，
只是把主观动作拆成可计算的步骤。

同一张图，十个人能画出十条趋势线。自动划线工具要解决的不是“画得更好看”， 而是把选点、拟合、容差、失效四件事写成可复现的规则 —— 这样它才能进入回测，而不是只停留在截图上。

TL;DR

先记住这三个结论

后面的所有算法，都是在为这三句话补细节。

01 划线 = 选点 + 拟合 + 容差

先决定哪些 K 线算“点”，再决定用哪几个点连线，最后用 ATR 或百分比决定“多接近才算碰到”。三步里任何一步换口径，画出来的线就不同。

02 “碰得多”不等于“有效”

一条线可以被价格反复触碰，也可以被反复穿越。质量分必须同时奖励触碰、跨度和贴合度，并惩罚穿越，否则会选出一条噪音线。

03 确认时间必须晚于拐点

拐点只有等右侧足够多的 K 线走完才能确认。用拐点当天去下单，等于把未来数据带进回测 —— 这是自动划线最常见的翻车方式。

01 / 地基

把 K 线变成“点”

趋势线不是直接画在收盘价上的。几乎所有算法都先把价格序列压缩成少量候选拐点， 再在这些点上做文章。候选点的定义，决定了后面所有结果。

1.1 分形枢轴：左右各看 N 根

一个高点如果比左侧 N 根和右侧 N 根的 high 都高，就被记为 pivot high； 低点同理。这是行情软件里 “Pivot High/Low” 最常用的定义，也是本项目 highLowPivots 的口径：默认左右各 5 根。

关键在右侧：第 i 根的高点，要等第 i+N 根走完才能确认。 所以每个点都要同时记录两个索引：idx（极值所在）和 confirmedAtIdx = idx + N（可用的时间）。任何交易信号都必须挂在后者上。

为什么不用“相等也算”的宽松写法？如果允许 >=，盘整区里一排等高 K 线会全部成为枢轴，候选点数量爆炸；严格大于更接近“这个位置确实突出”的本意。

1.2 ZigZag：用回撤幅度定义拐点

ZigZag 不要求局部极值，而是跟踪趋势方向：价格从高点回撤超过 pct（例如 3%）， 才把之前的高点确认为拐点；反弹超过 pct，才确认低点。

它比固定窗口更适应不同波动率，但 pct 本身是主观的： 3% 在螺纹钢日线上是正常波动，在茅台日线上可能几天都触发不了一次。

本项目 swingPoints 同时返回 idx 与 confirmedAt： 拐点在价格上成立，和它在时间上可用，不是同一根 bar。

1.3 经典枢轴点：用上一期的 H / L / C 算下一期

这类“Pivot Points”不是摆动点，而是根据上一日（或上一周、上一月）的最高、最低、收盘价， 算出下一期的若干固定价位。它们的关键纪律是：只能用已收盘的上一期数据， 并且只能画在下一期开始之后。

P = (H + L + C) / 3
R1 = 2P − L    S1 = 2P − H
R2 = P + (H − L)    S2 = P − (H − L)
R3 = H + 2(P − L)    S3 = L − 2(H − P)
口径中枢 P扩展方式适用场景
Standard(H+L+C)/3等距 R1–R3 / S1–S3最通用的日内/隔夜参考位
Fibonacci(H+L+C)/30.382 / 0.618 / 1.0 × 振幅把枢轴与黄金分割结合
CamarillaC1.1 × 振幅 ÷ 12、6、4、2短线反转/剥头皮，R3–R4 常作极端位
Woodie(H+L+2C)/4与 Standard 同构，中枢更偏收盘价收盘价权重更高的市场

本项目 src/analysis/pivots.js 只实现这四种。Demark 口径在各家软件里分支不一致， 没有把握写对就不放 —— 划线工具宁可少一个口径，也不要多一个“看起来像”的错口径。

02 / 趋势线

两个点连一条线，难的是选哪两个点

人眼会自动忽略噪音、挑“看起来重要”的拐点。算法没有这种直觉， 所以它通常要枚举大量组合，再用一套评分把“像趋势线”的候选留下。

2.1 最直接的做法：两两组合 + 触碰计数

给定一组枢轴点，对所有点对 (i, j) 连线，统计有多少个点到这条线的距离 小于容差 tol。触点数达到 minTouches（常见 2 或 3）才算候选。 早期实现甚至会对全部 K 线做三重循环，复杂度 O(N³)；先压成枢轴点后， 候选点数通常只有几十个，暴力枚举就够用了。

触碰判定：|Pk − line(xk)| ≤ tol
tol = 0.5 × ATR14（常见起点）或固定百分比
候选线：touchCount ≥ minTouches，且两点之间不出现与方向相反的严重穿越

2.2 拟合：两点定线，还是所有点一起定线

只管两个锚点的线，对第三个点是否贴合没有约束。更稳的做法是：先用两个点生成候选， 把所有“落在容差内”的点当作 inlier，再对 inlier 做一次最小二乘重新拟合。 这样线的斜率由所有触点共同决定，而不是被某两个点“绑架”。

slope = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)
intercept = (Σy − slope·Σx) / n

重拟合后要再数一次 inlier：有些点会掉出容差，有些新点会进来。通常迭代一两次就稳定。 这一步是 “两点线” 和 “统计线” 的分水岭。

2.3 评分与去重：只留最强的一条

候选线会很多，而且彼此高度相似。社区实现里比较完整的一套评分是 TradingView 生态中的 “Auto Trendlines” 口径：

score = touches × span × extreme_bonus × recency_bonus × fit_factor × violation_penalty

fit_factor     = 1 / (1 + avg_residual / tol)　（越贴合越高）
violation_penalty = 1 / (1 + violation% / 5)　　　（穿越越多越低）
recency_bonus 从 1.0（最新点就在当前）线性衰减到 0.2（最新点在回看边缘）
  • touches × span：既奖励“碰得多”，也奖励“管得久”。
  • extreme_bonus：从最极端的高/低点出发的线更可能是主趋势线。
  • violation_penalty：价格频繁穿过的线，斜率再漂亮也不可信。
  • greedy non-overlap：按分数从高到低选，每个枢轴最多贡献给一条线，避免画出三条几乎重合的线。

另一种去重方式是按 (斜率, 线的最新价格) 做二维聚类， 把“同一条走廊里的不同画法”合并，只保留组内最高分。两种做法目标一致： 图上的线越少，信息密度越高。

线不是越多越好。一张图上超过 5 条自动趋势线，读者会开始“看到自己想看到的线”。多数实现默认每个方向只留 1–3 条，这是有意的信息压缩。

03 / 硬数学

比“两点连线”更稳的四种方法

当噪音、影线、异常值很多时，纯粹的“两点定线”会非常脆弱。下面四种方法各自解决一类问题。

最小二乘 OLSLeast squares

对一组点找一条使纵向残差平方和最小的直线。它不要求线严格穿过任何两个点， 因此对单个异常点的敏感度低于“两点定线”。缺点是：普通最小二乘对离群值仍然敏感， 而且默认残差在两侧对称，不会主动把线推到所有点之外。

适合：触点较多、噪音相对均匀的候选线重拟合。

RANSACRandom Sample Consensus

反复随机抽两个点连线，统计有多少点落在容差内（inlier），保留 inlier 最多的一组， 再用全部 inlier 重拟合。它对“少数异常点 + 大量正常点”的结构非常稳。

枢轴点通常只有几十个，所以很多实现干脆枚举所有点对， 这等于一个确定性的 RANSAC：不用随机种子，结果可复现。

社区实现：pytrendline 的穷举扫描、TrendEdge 的 scipy 峰值 + RANSAC 拟合。

Hough 变换参数空间投票

把每个价格点映射到参数空间里的一条正弦曲线： ρ = x·cosθ + y·sinθ。许多点对应的曲线会在某个 (θ, ρ) 处相交， 交点票数越高，就越可能是一条真实存在的直线。

优点是不依赖“先选两个锚点”，能一次把所有候选线找出来； 缺点是参数离散化很关键，而且容易在密集点区域产出大量近似线， 所以工程上要加权重、合并相近直线、限制候选数量。

学术参考：Jitpakdee & Pravithana 的 Hough 趋势线生成方法；trendln 也提供 Hough 模式。

分位数回归Quantile regression

普通回归拟合“条件均值”，分位数回归拟合条件分位数。取 τ = 0.9 拟合高点序列， 得到的线倾向于把所有点包在下方，适合做压力线；取 τ = 0.1 拟合低点序列， 适合做支撑线。

它不需要先选出“哪两个点”，而是让整组极值共同决定位置， 因此比“最外侧两点连线”更稳，也更不容易被单根长影线带偏。

国内券商研报里常见口径：120 日回溯、5 日局部高低点、压力线 τ=0.9、支撑线 τ=0.1。

凸包Convex hull

对高点序列求上凸包、对低点序列求下凸包，得到的折线是“所有点都在一侧”的 最严格包络。Andrew 单调链算法在点已按时间排序时是线性的。

优点是数学上绝对不穿越价格；缺点是震荡行情里会碎成很多短边， 看起来像一堆无关的线段。它更适合作为“主包络参考”，而不是主要信号线。

社区实现：pine-scripts 的 Auto Trendlines 把凸包做成可选叠加层。

04 / 水平位

水平支撑阻力：聚簇往往比连线更稳

趋势线回答“沿着这个斜率，哪里是边界”；水平位回答“这个价格附近，历史上被尊重过几次”。 后者对趋势方向的假设更少，因此在震荡和转折里更常用。

4.1 把相近的枢轴合并成一个价位

先找 pivot high / low，再把彼此距离小于 pctbound（例如 0.2%–5%， 视周期和品种而定）的点聚成一簇。簇内点数就是 触碰次数， 簇的中心价（均值或中位数）就是这条水平位。

常见实现有两种：按相对距离顺序扫描合并，或用层次聚类 （AgglomerativeClustering）一次性分组。前者的结果依赖扫描顺序， 后者更稳定但需要指定距离阈值。

4.2 强度不只等于触碰次数

  • 触碰次数：最直观，但老价位会天然占优。
  • 新鲜度：越久没被触碰的位，参考价值越低。
  • 触碰时的量能：放量触碰后收回，通常比缩量擦一下更有意义。
  • 是否已被收盘穿越：被收盘价有效突破的位，应从“支撑/阻力”降级为历史位。

本项目 highLowPivots 会给每条线算 brokenAtIdx： 线在首次被收盘价穿越的那根截止，而不是一路拖到图的最右边。

4.3 从“线”到“区”：供需区与订单块

真实市场里支撑阻力很少是一条精确到小数点的线，更像一个带宽度、会失效的区间。 供需区的常见定义是：一段窄幅整理（base）之后，出现一根明显脱离的 K 线。 本项目用 ATR 把“窄幅”和“脱离”量化：

base　：1–3 根连续 bar，每根 (high − low) ≤ 0.6 × ATR14
departure：随后 3 根内，收盘价离开 base 边界 ≥ 1.2 × ATR14
失效　：收盘价反向穿越 base 的另一侧 → broken，色带截止在穿越那根

这类区间比单根水平线更贴近“订单在这里成交过”的直觉，但也更容易过拟合门槛。 所以参数要用同一个品种的历史数据校准，而不是从别人的截图里抄。

05 / 通道

通道：把一条线变成两条线

趋势线给出一个边界；把边界平移或按波动率扩展，就得到通道。 通道的价值在于同时表达“方向”和“正常波动范围”。

5.1 平行通道

最常见做法：先拟合主趋势线，再统计价格到这条线的最大偏离（或某个分位数偏离）， 在另一侧画一条平行边。通道宽度可以用价格差、百分比或 ATR 倍数表示。

TradingView 社区的自动趋势线指标会为每条线加一个“触碰区域”： 以线的两个锚点处的 ATR 均值为基础，取一半作为容差带。 这解释了为什么同一条线在不同波动率环境下看起来“宽度不同”。

5.2 三类经典通道

  • Donchian：过去 N 根的最高 high 与最低 low。海龟交易法的突破通道。
  • Keltner：EMA ± k × ATR。比布林带更抗跳空。
  • Bollinger：均线 ± k × 标准差。衡量波动率扩张/收缩。

本项目的 donchianBreak 策略就是 Donchian 通道突破； dualThrust 用前 N 日振幅构造上下轨；trendRegime 则把均线/ADX 与放量突破组合。

通道状态比单条线更有信息量：上下轨同时上移 = 上升通道；同时下移 = 下降通道；上轨下移、下轨上移 = 收敛（挤压，常对应突破前夜）；上轨上移、下轨下移 = 扩张（波动率放大）。

06 / 信号

突破与回踩：把线变成可回测的事件

线画出来只是第一步。要让划线进入回测，必须定义“什么时候算突破”“什么时候算确认”， 并且把成交时间定在信号之后。

突破的三种常见定义

  1. 单根收盘穿越：收盘价超过线 + 容差。最快，也最容易假突破。
  2. 连续 N 根收盘：TradingView 自动趋势线的默认是连续 3 根收盘落在另一侧。更稳，但入场更晚。
  3. 幅度 + 量能：穿越幅度 ≥ k×ATR，且成交量 ≥ 均量 × 倍数。过滤掉无量假破。

本项目回测统一采用“信号在第 i 根产生，成交在第 i+1 根开盘”，不提供“当根成交”开关。

回踩确认

突破后价格回到线附近，但没有收盘跌回另一侧，然后再次离开 —— 这才算回踩确认。 工程上通常要求：回踩距离 ≤ 容差（如 0.5 ATR），且收回的那根收盘仍在突破方向。

回踩确认能显著降低假突破，但会牺牲一部分行情。它适合“宁可少做，不要做错”的趋势系统， 不适合追求极早期入场的系统。

突破信号（做多示例）：close > line + tol　且　close − line ≥ k × ATR　且　volume ≥ avgVol × m
回踩确认：价格回到 line ± tol 区间，但 close 未跌破 line − tol
失效：close 跌回 line 的另一侧超过 tol，或连续 N 根收在线下
07 / 风险

未来函数：自动划线最容易翻车的地方

一条线在事后看总是“刚刚好”。真正的问题是：在当时的那个时间点，这条线能被画出来吗？

7.1 三种典型泄露

  • 拐点时间错位：用 idx 而不是 confirmedAt 下单。拐点当天根本不知道它是拐点。
  • 重绘（repainting）：新 K 线出现后，历史线被改掉。看图很准，实盘不可复现。
  • 全样本拟合：用整段数据算出的分位数/均值/通道宽度，再拿去解释早期行情。指标“知道”了未来。

7.2 五问自检清单

  1. 这条线在 t 时刻的值，是否只依赖 t 及之前的数据？
  2. 枢轴点的右侧窗口，是否已经完整走完？
  3. 新增一根 K 线后，历史线段会不会移动或消失？
  4. 通道宽度/分位阈值，是用滚动窗口还是全样本算的？
  5. 信号产生的下一根开盘价，是否真的可成交（涨跌停/停牌/流动性）？

本项目的分析层只接收“已揭示”的 bar 切片；src/validation/leakProbe.js 用前缀一致性与未来不变性做机器门禁，而不是靠代码 review 兜底。

“回测很漂亮”不是算法有效的证据。自动划线参数多、自由度大，极容易在样本内找到一条“神线”。至少要在样本外、不同品种、不同成本假设下都能站住，才值得继续研究。

水平位合并阈值0.2%–0.5%（日线）更多枢轴被合并，位更少更粗位更细，但可能把同一价位拆成多条
突破确认根数2–3 根收盘假突破更少，入场更晚更早入场，也更容易被打脸

一个实用原则：先固定容差和最少触点数，再调回看长度。 前者决定“什么叫一条线”，后者决定“看多远”。反过来调，会同时改变两件事，无法判断结果变化来自哪里。

09 / 本项目

这些算法在本项目里落在哪

本项目的划线分两层：手动工具负责“你自己画”，分析叠加层负责“按规则自动算”。 两层共用同一套图表坐标系，但自动层只吃已揭示的 K 线。

能力入口口径要点
手动划线 终端工具条：水平线 / 线段 / 射线 / 测量尺 / 盈亏比 磁吸到最近 K 线的高/低/开/收；测量尺给点数、涨跌幅与周期数
经典枢轴点 src/analysis/pivots.js Standard / Fibonacci / Camarilla / Woodie；上一期 HLC 只画在下一期
分形摆动高低点 highLowPivots 左右各 N 根；同价位 0.2% 内合并并累计触碰次数；收盘穿越即 brokenAtIdx
ZigZag 摆动点 swingPoints（src/analysis/common.js） 相对回撤阈值；返回 idx 与 confirmedAt，两者不混用
供需区 / Wyckoff src/analysis/zones.js ATR 定义 base 与脱离；spring / upthrust / SOS / SOW 只做可核验的部分
动态支撑阻力 src/analysis/supertrend.js Wilder 递推，final band 不允许往回缩
成交量分布 src/analysis/volumeProfile.js POC / 价值区；uniform 分箱，不用单点 typical price 法
形态识别 src/analysis/patterns.js 基于摆动点的头肩/双顶等几何规则；每个形态带 confirmedAtIdx
通道突破策略 src/strategy/library.js Donchian / Dual Thrust / 趋势区间过滤 / N 字量价；信号次日开盘成交
前视门禁 src/validation/leakProbe.js 前缀一致性 + 未来不变性；机器判定，不依赖人工 review

想直接体验：打开终端后，在图表上方的「辅助」区切叠加层，或在工具条里手动画线； 自动回测页签里的 Donchian / Dual Thrust 策略，本质就是本章讲的通道突破。

10 / 来源

调研来源与延伸阅读

本页的算法口径来自以下公开资料与开源实现（调研于 2026-10-29）。 外部链接可能更新；具体默认参数以各项目文档为准。

  • TradingView：自动趋势线（官方说明） 枢轴 25/25 与 5/5、ATR 过滤、触碰区域、延伸长度与突破根数的完整口径。
  • Trendoscope：Auto TrendLines & Support Resistance 社区里较完整的自动趋势线实现，强调触碰权重、角度与线质量。
  • Neural Engine：Adaptive Trendline Detection 多时间尺度锚点 + 斜率优化 + 触碰评分，只保留一条支撑与一条阻力。
  • pine-scripts：Auto Trendlines 文档 点对枚举、OLS 重拟合、ATR 容差、复合评分、贪心去重与凸包的工程细节。
  • pytrendline 基于枢轴的两点扫描与评分，文档明确说明最坏复杂度 O(N³) 及去重聚类。
  • trendln 局部极值、OLS 趋势线、Hough 模式与水平位聚簇的 Python 实现。
  • Hough 变换生成趋势线（论文） 把趋势线检测写成参数空间投票问题，并讨论候选线合并。
  • 压力线与支撑线的识别算法及突破策略 国内研报口径：120 日回溯、5 日局部极值、分位数回归构造包络线。
  • MQL5：最小二乘法拟合趋势线 EA 从拐点识别到最小二乘拟合、再到触碰触发的完整工程示例。
  • Algorithmically drawing Trend Lines 重缩放、拐点检测、Hough 变换、过滤的入门流程。
